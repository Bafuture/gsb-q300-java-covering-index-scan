## 实现说明：列存延迟物化组件

> 本仓库实际实现的提示词为「列存延迟物化组件」（以对话中的 User Prompt 为准），
> 实现位于 `com.example.gsb.latemat` 包。

### 组件结构

| 类 | 职责 |
|----|------|
| `ColumnStoreTable` / `Column`（`IntColumn`/`LongColumn`/`DoubleColumn`/`StringColumn`） | 按列存储；每次单元格读取都计数，未触碰的列读取量为 0 |
| `Predicate` / `Op` / `Query` | 单列筛选条件与「合取条件 + 输出列」查询 |
| `CandidateSet` | 候选集（升序行号列表）；`filter` 只读筛选列在候选行号处的值，逐步缩小 |
| `LateMaterializationEngine` | 核心引擎：候选集构造 → 多列依次过滤 → 按行号物化输出列；支持 LATE/EARLY/AUTO 策略与并发执行 |
| `FullScanExecutor` | 基线：全列全行读取再筛选，用于正确性与读取量对比 |
| `QueryStats` | 候选集大小、读取/跳过列数、顺序/随机单元格读取量、物化列数、策略与耗时 |

### 延迟物化流程

1. 第一个筛选条件整列顺序扫描，构造候选集（只读该列，其它列零读取）；
2. 后续条件只在前一阶段的候选行号处取值过滤，候选集逐步缩小；
3. 筛选完成后才按最终行号物化输出列（随机回列取值）。

### 选择性评估与策略切换条件

代价模型：顺序读取一个单元格代价为 1，按行号随机读取代价为 α
（`randomAccessPenalty`，默认 4）。对剩余 k 个待读列：

- 延迟物化代价 ≈ α·c·k（c 为当前候选行数，随机访问）
- 提前物化代价 ≈ N·k（顺序整列读取后逐行筛选）

**切换条件：c/N > 1/α（默认即存活行占比 > 25%）时 AUTO 切换为提前物化。**
某列条件选择性过低（通过行太多）时，继续按行号随机回列取值不如顺序读完全列。

### 耗时对比（30 万行 × 24 列宽表，模拟磁盘随机寻址 500ns/次）

```
[耗时对比] 低选择性(60%通过): LATE=407.28ms vs EARLY=45.08ms → 提前物化更划算
[耗时对比] 高选择性(1%通过):  LATE=12.30ms vs EARLY=40.40ms → 延迟物化更划算
```

与代价模型估值方向一致（低选择性 LATE≈460 万 vs EARLY≈360 万代价单位；
高选择性 LATE≈37 万 vs EARLY≈360 万）。测试用 `DiskSimulatingColumn`
模拟存储层顺序/随机访问延迟差异，纯内存数组无法体现该差异。

### 并发执行

`executeParallel(query, threads)` 把行号区间均分给多线程，每个分片独立构造
候选集并物化，最后按区间顺序合并，输出行保持行号升序；各分片统计合并后与
单线程总量一致（有测试验证 1/2/3/4/8 线程结果与顺序执行完全一致）。

### 统计指标（`QueryStats`）

- `candidateSetSizes()`：每个筛选阶段后的候选集大小（逐步缩小）
- `readColumnCount()` / `skippedColumnCount()`：读取/跳过的列数
- `sequentialCellReads()` / `randomCellReads()`：顺序/随机单元格读取量
- `skippedCellReads()`：相对全列全行读取基线省下的列读取量
- `materializedColumns()`：物化的输出列数（对比 `FullScanExecutor` 的全列物化）
- `estimatedCost()` / `strategiesUsed()` / `elapsedNanos()`

（LATE/EARLY/AUTO/并发 vs 全量读取基线，60 轮随机表+随机查询）、
策略切换阈值与耗时对比、并发合并保序、统计指标。
